# artifact-generation Delta — adm-artefact-conformance

## ADDED Requirements

### Requirement: Document Control And Generation Footer Conformance
Every shipped template that renders a Document Control table SHALL enumerate
all 14 standard fields of the quality checklist in canonical order:
Document ID, Document Type, Project, Classification, Status, Version,
Created Date, Last Modified, Review Cycle, Next Review Date, Owner,
Reviewed By, Approved By, Distribution — a template SHALL NOT ship a
subset that lets a generated artefact fail checklist common check #1.
Templates may carry additional type-specific rows (e.g. `Change ID`,
`Severity Weighting`); a subset is not permitted. The revision-history
table header SHALL be the canonical six-column form
`Version, Date, Author, Description, Reviewer, Approver` across templates,
the quality checklist, and generated artefacts. The generation footer of
every artefact SHALL carry all five fields: Generated by, Generated on,
ArcKit Version, Project, and Model.

#### Scenario: ADM template carries the full 14-field table
- **WHEN** the Document Control table of an ADM template (e.g.
  `adm-preliminary-template.md`, `capability-map-template.md`) is inspected
- **THEN** it lists all 14 canonical fields (placeholders permitted), so an
  artefact rendered from the template passes checklist check #1

#### Scenario: checklist revision-history columns match the templates
- **WHEN** the quality checklist's common check #6 (all copies) is read
- **THEN** it lists `Version, Date, Author, Description, Reviewer,
  Approver` — identical to the templates' revision-history headers

#### Scenario: generated artefact footer includes Model
- **WHEN** an artefact's generation footer is inspected
- **THEN** it carries Generated by, Generated on, ArcKit Version, Project,
  and Model (e.g. `**Model**: Codex (OpenAI)`)

### Requirement: Shipped Templates Are Renderable Conforming Examples
The mermaid diagrams shipped inside templates SHALL be syntactically valid
as shipped: `quadrantChart` axis lines SHALL use the `x-axis L --> R` /
`y-axis L --> R` form (no `x-axis__` / `y-axis__` typos) and every plot
point SHALL use the array form `"Name": [x, y]` (no bare-comma
coordinates, no comma-separated points).

#### Scenario: capability-map template diagram parses
- **WHEN** the `quadrantChart` block in `capability-map-template.md` is
  parsed by a mermaid renderer
- **THEN** the axis lines read `x-axis Low --> High` / `y-axis Low -->
  High` and plot points use the `"C1.1.1": [0.8, 0.3]` array form, so the
  diagram renders instead of failing to parse

#### Scenario: no axis typo or comma-form point ships
- **WHEN** the ADM and agent-architecture template trees are scanned
- **THEN** no file contains `x-axis__` or `y-axis__`, and no
  `quadrantChart` block uses a bare-comma or comma-separated plot point
