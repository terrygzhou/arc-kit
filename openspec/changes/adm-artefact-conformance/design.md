# ADM Artefact Conformance — design

## Context

The quality checklist is the contract: common check #1 demands 14
Document Control fields, #6 demands a revision-history table, #7 demands a
generation footer with five fields (incl. `Model`). The shipped ADM
templates predate the 14-field rule (they carry 7-field tables), so
template-driven generation systematically produces non-conforming artefacts.
The BPCM artefact (6.8.0) was manually conformed by the generating agent —
proof the field set is renderable — but the template itself still ships the
subset, so the next generation regresses. `scripts/sync-shared-assets.py`
keeps the 31 `quality-checklist.md` copies in lockstep;
`scripts/converter.py` regenerates `extensions/*`.

## Goals / Non-Goals

**Goals:** make the 14-field Document Control table and the canonical
revision-history columns a single-source invariant (template ⇄ checklist
⇄ artefact); ship renderable template diagrams; remediate project 001.

**Non-Goals:** DISC template rework; OAA template audit; interview-flow
changes; hand-editing generated `extensions/*`.

## Decisions

- **Template side carries the fix, not the artefacts.** Expanding the
  templates (both trees) is the only durable fix: the checklist stays the
  rule, the template becomes the conforming example, and generation from
  the template cannot undercut the checklist. The two trees
  (`plugins/arckit-claude/plugins/togaf/adm/templates/` and
  `plugins/arckit-togaf-adm/templates/`) are edited identically; their only
  intended drift is the `Generated by` command-namespace line.
- **Checklist → template direction for revision-history columns.** The
  six-column header `Version | Date | Author | Description | Reviewer |
  Approver` is already in all 11 ADM templates and both generated artefacts
  (majority + artefacts agree); the 32-copy checklist wording is the
  outlier, so the checklist is reworded, not the templates.
- **Field names follow the checklist order.** Templates use the canonical
  14-field order and names (Document ID, Document Type, Project,
  Classification, Status, Version, Created Date, Last Modified, Review
  Cycle, Next Review Date, Owner, Reviewed By, Approved By, Distribution).
  `architecture-repository` loses its duplicate Owner row;
  `architecture-change` keeps its extra rows (Change ID, Change Type,
  Priority) — extras are permitted, a subset is not. Per-template Review
  Cycle values mirror the command instructions ("Monthly during active ADM
  cycle" etc.); `application-inventory` (no command-side instruction) uses
  the `[REVIEW_CYCLE]` placeholder, consistent with other template
  placeholders.
- **TDD the template invariant.** A focused pytest asserts 14-field
  presence, valid mermaid, and the canonical revision-history header —
  run RED before the edits, GREEN after, so regression is caught in CI.
- **Project 001 remediation is data, not code.** The ADMP Document Control
  expansion mirrors the BPCM values (Reviewed By CISO, Approved By
  Postmaster General, Distribution org default) with `Last Modified` =
  remediation date 2026-09-02; provenance entries are *recorded
  retroactively* and explicitly marked "backfilled 2026-09-02", matching
  the existing remediation-record convention in both intake JSONs.

## Risks / Trade-offs

- **32-copy checklist sed can miss a variant.** Mitigation: a post-edit
  grep asserts zero remaining `Changes, Approved By` lines in tracked
  files, and `sync-shared-assets.py --check` confirms lockstep.
- **`architecture-repository` uses "Standard ID" deliberately**
  (`ARC-000-REPO` is a global standard, not a project artefact). Renaming
  the row to "Document ID" standardises the column set; the value keeps
  `ARC-000-REPO-v[VERSION]`.
- **Template `Review Cycle` values are policy-ish.** Where the command
  text prescribes a cycle we mirror it; where it does not we ship a
  placeholder rather than invent policy.
- **DISC stays non-conforming on check #1 by construction.** Flagged as a
  follow-up change; accepted now because DISC has no Document Control
  section at all (different rendering path via `{{ }}` placeholders).
