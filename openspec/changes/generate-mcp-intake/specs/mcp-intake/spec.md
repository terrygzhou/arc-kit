# mcp-intake Delta — generate-mcp-intake

## ADDED Requirements

### Requirement: Generated Intake Data Is Emitted From Template Question Blocks
The arckit-mcp package SHALL contain a generated module `arckit_mcp/intake.py`,
emitted by `scripts/generate-mcp-intake.py` (arc-kit repo) from the
`## Intake Interview Questions` blocks in template files under
`plugins/*/templates/` and `plugins/arckit-claude/plugins/*/templates/`, plus
MANDATORY prerequisite inputs taken from the same command-markdown tier
headers that `generate-mcp-gates.py` already parses. **Dedup rule: the flat
tree wins.** When the same doc-type code is covered by a flat-tree template
and a nested duplicate (the oaa `agile-strategy-template.md` pair, doc-type
`OASTR`, differs only in one command-namespace string), the flat entry is
authoritative; the nested copy is discarded. Scanning is in sorted-path
order so output is deterministic. The module SHALL
declare, with the standard "Generated by … — DO NOT EDIT BY HAND" header
used by `generate-mcp-registry.py`:

- `INTAKE: dict` — keyed by **doc-type code** (e.g. `"REQ"`, `"BPCM"`),
  value shape `{"questions": [str, …], "mandatory_inputs": [str, …],
  "source": "<template-path>"}`, where `questions` is the union of the
  template's question block and the command's MANDATORY prerequisite input
  prompts, and `mandatory_inputs` records which inputs are structural
  (block when missing, per the gate requirement below).
- `COVERAGE: dict` — per doc-type code, either `"covered"` or `"no-static-questions"`
  (doc-types whose core-plugin template has no question block, e.g. every
  `arckit-claude`-only doc-type). `COVERAGE` SHALL be rendered into the
  module as data so a consumer can warn loudly rather than fail silently.

The generator SHALL follow the established `generate-mcp-*.py` conventions:
pure Python/regex parsing (no node), output path from `ARCKIT_MCP_ROOT`
env or a CLI argument defaulting to the sibling `arckit-mcp` checkout.

#### Scenario: Regeneration is byte-stable
- **WHEN** `python scripts/generate-mcp-intake.py` is run twice against an
  unchanged tree
- **THEN** both runs emit a byte-identical `arckit_mcp/intake.py`

#### Scenario: Dedup guarantees a single source per doc-type
- **WHEN** the generator encounters doc-type code `OASTR` in both the flat
  tree (`plugins/arckit-oaa/templates/agile-strategy-template.md`) and a
  nested duplicate (`plugins/arckit-claude/plugins/arckit-oaa/templates/…`)
- **THEN** `INTAKE["OASTR"]["source"]` points to the **flat-tree** path
  only; the nested copy is discarded entirely (questions and MANDATORY
  inputs both come from the flat template)

#### Scenario: Core-plugin doc-types are flagged, not silently empty
- **WHEN** a doc-type's effective core template (`plugins/arckit-claude/templates/`)
  has no `## Intake Interview Questions` block
- **THEN** `COVERAGE` marks it `"no-static-questions"` and the emitted module
  exposes that flag, so a consumer can print a coverage warning instead of
  returning an empty question list as if it were complete

#### Scenario: Overlay templates produce real questions
- **WHEN** the generator runs over `plugins/arckit-togaf-adm/templates/`
  (12 templates with question blocks) and `plugins/arckit-it4it/templates/`
  (6)
- **THEN** `INTAKE` contains a non-empty `questions` list for the
  corresponding doc-type codes, sourced from those templates' blocks

### Requirement: Server Intake Lookup Falls Back To Placeholder Per Doc-Type
`server.py`'s `_intake_questions()` SHALL look up the command's doc-type in
`intake.INTAKE` and return the derived questions when present. When the
doc-type is absent from `INTAKE` or is marked `"no-static-questions"` in
`COVERAGE`, it SHALL fall back to the existing synthetic per-doc-type
placeholder question, so no command's intake payload ever becomes empty.

#### Scenario: Covered doc-type returns derived questions
- **WHEN** `run_command` is called for a command whose doc-type has
  `COVERAGE[code] == "covered"`
- **THEN** the `intake` field of the response contains the template-derived
  question list, not the placeholder

#### Scenario: Uncovered doc-type degrades to placeholder
- **WHEN** `run_command` is called for a doc-type with
  `COVERAGE[code] == "no-static-questions"`
- **THEN** the `intake` field contains the previous placeholder question
  (one per doc-type code), preserving today's behavior

### Requirement: Intake-Completeness Gate Is Soft And Structural
The intake-completeness check folded into `check_gates` (called from
`run_command` at L423–424) SHALL block only on **structurally missing
MANDATORY prerequisite inputs** (items in `INTAKE[...]["mandatory_inputs"]`
with no saved value). Questions the user skipped — rendering as `TBD` —
SHALL NOT block. Bulk `arckit-build` mode SHALL remain non-interactive: it
reads saved `.arckit/intake/` answers and SHALL NOT trip the soft gate on
unanswered questions.

#### Scenario: Skipped question renders TBD without blocking
- **WHEN** a user skips an intake question and `run_command` advances
- **THEN** `gate_blocked` is not raised for that question; the artefact
  renders the `TBD` marker quoting the question

#### Scenario: Missing MANDATORY input blocks
- **WHEN** a doc-type's `mandatory_inputs` names a prerequisite artefact
  (e.g. `PRIN` for OAA commands) that does not exist in `projects/`
- **THEN** `gate_blocked` includes that input and the command stops,
  matching `check_gates`'s existing hard-stop semantics for MANDATORY tiers

#### Scenario: Bulk build is not interrupted by unanswered questions
- **WHEN** `arckit-build` runs a target whose saved `.arckit/intake/`
  answers are incomplete
- **THEN** the build proceeds, rendering `TBD` for the missing answers,
  and only stops where a structural MANDATORY input is absent

### Requirement: persist_intake Is A Read/Seed Tool, Not A Write Path
A new MCP tool `arckit.persist_intake` SHALL be registered in `server.py`
(alongside `arckit.persist_artifact`) that **reads** saved
`.arckit/intake/{command-stem}.json` answers for a project and returns them
as prefill data for bulk builds. The tool SHALL NOT write answers: Agent A
(the interview owner) remains the sole persister, preserving the relay
constraint that the server never proxies user I/O.

#### Scenario: Bulk build seeds from saved answers
- **WHEN** `arckit.persist_intake` is called for a project with existing
  `.arckit/intake/requirements.json`
- **THEN** it returns the parsed answers so a bulk run can prefill the
  interview without prompting the user

#### Scenario: No write path for answers through the server
- **WHEN** the tool set is inspected
- **THEN** no MCP tool writes to `.arckit/intake/`; persistence of answers
  remains agent-side
