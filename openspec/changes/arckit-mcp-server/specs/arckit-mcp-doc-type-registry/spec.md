## Purpose
Defines the MCP-side mirror of `doc-types.mjs` / `SUBDIR_MAP` / `MULTI_INSTANCE_TYPES` so that tool descriptions, gate checks, and artefact persistence use the same codes as the plugin. The mirror is kept in sync by a CI test; a code missing from the mirror that a command writes is an error.

## ADDED Requirements

### Requirement: The MCP Registry Mirrors doc-types.mjs
The MCP server SHALL maintain a registry of all doc-type codes that is byte-equivalent to `plugins/arckit-claude/config/doc-types.mjs`. Each entry SHALL include: `code`, `name` (display name), `category`, `regime` (optional), and `severity` (optional). The registry SHALL be generated from the source of truth at build time or loaded at runtime via a static copy; the copy SHALL be regenerated by CI on every change to `doc-types.mjs`.

#### Scenario: Registry matches the source of truth
- **WHEN** CI runs `tests/plugin/test_mcp_command_registry.py`
- **THEN** every code in `doc-types.mjs` is present in the MCP registry with matching `name`, `category`, `regime`, and `severity` fields, and no extra codes exist in the registry that are absent from `doc-types.mjs`

#### Scenario: A new doc-type added to the source is picked up
- **WHEN** a developer adds a new code `XYZ` to `doc-types.mjs` and runs `python scripts/converter.py` (or the equivalent registry regeneration step)
- **THEN** the MCP registry is updated to include `XYZ` with its display name and category

### Requirement: SUBDIR_MAP Is Mirrored
The MCP server SHALL maintain a `SUBDIR_MAP` that maps each multi-instance doc-type code to its subdirectory (e.g. `ADR` → `decisions`, `DIAG` → `diagrams`, `RSCH` → `research`). The map SHALL be byte-equivalent to the `SUBDIR_MAP` in `doc-types.mjs`.

#### Scenario: ADR artefacts land in decisions/
- **WHEN** the agent calls `arckit.persist_artifact` with `doc_type: "ADR"` and `project_id: "001"`
- **THEN** the artefact is written to `projects/001/decisions/ARC-001-ADR-001-v1.0.md`

#### Scenario: RSCH artefacts land in research/
- **WHEN** the agent calls `arckit.persist_artifact` with `doc_type: "RSCH"` and `project_id: "001"`
- **THEN** the artefact is written to `projects/001/research/ARC-001-RSCH-v1.0.md` (no sequence number, per `MULTI_INSTANCE_TYPES`)

### Requirement: MULTI_INSTANCE_TYPES Is Mirrored
The MCP server SHALL maintain a `MULTI_INSTANCE_TYPES` set that mirrors the space-separated list in `generate-document-id.sh` (both copies: `scripts/bash/` and `plugins/arckit-claude/scripts/bash/`). A code in this set SHALL get a `-{NNN}` sequence number in its filename; a code not in this set SHALL NOT.

#### Scenario: ADR gets a sequence number
- **WHEN** the agent calls `arckit.persist_artifact` with `doc_type: "ADR"` and `project_id: "001"`
- **THEN** the filename includes `-{NNN}` (e.g. `ARC-001-ADR-001-v1.0.md`)

#### Scenario: REQ does not get a sequence number
- **WHEN** the agent calls `arckit.persist_artifact` with `doc_type: "REQ"` and `project_id: "001"`
- **THEN** the filename is `ARC-001-REQ-v1.0.md` (no `-{NNN}` segment)

#### Scenario: Parity with generate-document-id.sh
- **WHEN** CI runs the multi-instance parity check
- **THEN** the MCP's `MULTI_INSTANCE_TYPES` set is identical to both bash script copies; a missing code fails the test
